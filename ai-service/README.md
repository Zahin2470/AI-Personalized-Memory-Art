# Memory Art — AI Service

FastAPI service that wraps xAI's Grok APIs for every AI-heavy feature:
memory analysis (emotion/story/titles/tags), artwork generation, multi-memory
timeline narratives, and voice-note transcription. The Node backend calls
this over HTTP — it's a separate service so it can be scaled or redeployed
independently.

## Setup

```bash
cd ai-service
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env`:
- `XAI_API_KEY` — from https://console.x.ai
- `CLOUDINARY_*` — optional but recommended; without it, generated image
  URLs point at xAI's own temporary hosting instead of a permanent home
- `ALLOWED_ORIGINS` — should include wherever the Node backend runs

```bash
uvicorn app.main:app --reload --port 8000
```

Visit `http://localhost:8000/docs` for interactive API docs (Swagger UI,
auto-generated by FastAPI).

## Endpoints

| Method | Route               | Purpose                                                   |
|--------|----------------------|-------------------------------------------------------------|
| GET    | `/health`             | Health check + config status                                |
| POST   | `/analyze`             | `{ description, photo_urls[], location, dates[] }` → emotion, curated color palette, 2-4 sentence story, 3 suggested titles, tags |
| POST   | `/artwork/generate`    | `{ description, style, emotion, location, title }` → generated image URL + prompt used |
| POST   | `/timeline`            | `{ entries: [{label, date, description}] }` → chronologically-ordered narrative |
| POST   | `/transcribe`          | `{ audio_url, language }` → `{ text, language, duration }`, via Grok STT |

## Design notes

- **Emotion → color palette** is deliberately *not* left to the model to
  freehand hex codes. Grok classifies the memory into one of 8 curated
  emotion labels (`app/services/emotion.py`), and a hand-picked palette is
  mapped from there — more reliable and better-looking than trusting an LLM
  with color theory.
- **Vision**: photo understanding uses Grok's multimodal chat completions
  (same endpoint as text, `image_url` content parts) — the photos must be
  publicly reachable URLs, which is why Part 2 also swapped the backend's
  upload storage to Cloudinary.
- **Image generation** re-hosts the result on Cloudinary immediately
  (`app/services/storage.py`) since xAI's own generated-image URLs aren't
  guaranteed to stay valid long-term.
- **Model names** (`GROK_TEXT_MODEL`, `GROK_IMAGE_MODEL` in `.env`) are
  configurable — set to `grok-4.5` / `grok-imagine-image-quality` as of
  mid-2026, but check https://docs.x.ai/developers/models if your account
  has different access.
- **Transcription** uses xAI's Speech-to-Text API (`grok-stt`, launched
  April 2026). Unlike the chat/image endpoints, `/v1/stt` takes raw audio
  bytes over multipart form data, not JSON — so `POST /transcribe` here
  takes a URL (the voice note's Cloudinary URL), fetches the bytes itself,
  then re-uploads them to xAI. This was the one integration in the whole
  build where I had lower confidence in the exact request shape going in;
  I cross-checked a concrete `curl`/`requests` example against three
  independent sources (including a direct quote of xAI's own docs page)
  before writing `app/services/grok_client.py::transcribe`, but it's worth
  a manual test before relying on it in production.

## Verified

- Clean `pip install`, every file passes `py_compile`
- App boots via FastAPI's TestClient, `/health` and `/docs` both respond
- Route registration confirmed: `/analyze`, `/artwork/generate`, `/timeline`,
  `/transcribe`
- Request validation confirmed (missing required field → 422)
- Palette mapping and prompt-building logic unit-tested directly

Not tested: actual calls to the Grok API or Cloudinary, since this sandbox
can't reach `api.x.ai` or Cloudinary — you'll want to smoke-test `/analyze`,
`/artwork/generate`, and `/transcribe` yourself once your `XAI_API_KEY` is
in place.
